## 开发方验证记录

- Linux x86_64；Go 服务在 Docker `golang:1.24-alpine` 运行。`gofmt`、`go test ./...`、`go vet ./...`、`go build ./cmd/server`、`sh -n scripts/*.sh`、Node `--check` 内嵌 Web JavaScript 语法及 `git diff --check` 通过。Go 回归测试覆盖 MCP 本地 HTTP、读工具、来源、缺失/篡改签名拒绝及有效签名写入；页面回归测试核对可编辑标签字段和非安全上下文签名拦截。
- Chromium（Playwright CLI 1.62.0）实际浏览器操作：创建并编辑记忆，修改标签并确认 SQLite/API 返回新标签，按标签筛选，软删除、恢复；验证默认知识库删除的 409 错误反馈、项目间记忆隔离。390×844 视口下 `scrollWidth=390`、单列布局，无横向溢出。
- 同一浏览器访问 `http://10.3.0.7`：实测 `isSecureContext=false` 且 `crypto.subtle` 不可用；页面显示警告，写操作在确认及密钥提示前被拦截。localhost HTTP（Chromium 判定安全上下文）和真实写入通过。非 localhost 写入需 HTTPS；非安全 HTTP 读取仍可能明文传输，只可在可信加密内网或 HTTPS 使用。
- 真实客户端 MCP：Pi 1.6.0 与 Codex CLI 0.171.0（Linux x86_64，OpenAI Codex `gpt-6-luna`）均经本地 `/mcp` 调用 `memory_search` 和带测试 HMAC 签名的 `memory_save` 成功，返回/持久化结果可核对。Pi 缺少必填签名时在客户端 Schema 校验拒绝；Codex 默认 headless `approval=never` 首次因 MCP 需审批而拒绝，改用 `--approve-for-me` 后读写成功。测试签名证明协议链路，不证明用户确认或严格逐次授权；来源展示为知识库名称/类型，模型暂未记录来源 Agent 字段，边界见[设计记录](../待确认问题.md)。
- 本机真实 Skill：Pi 1.6.0 通过 `--skill` 加载仓库 Skill；Codex CLI 0.171.0 从临时 `CODEX_HOME/skills` 加载仓库 Skill，未修改用户全局配置。两者实际调用 `mem-search.sh` 检索默认项目、明确指定的另一项目及共享库；`mem-save.sh` 生成默认项目和指定共享库的 mode 0600 Secure 请求，独立审批 CLI 写入后再由 Skill 检索，标签经详情 API 核对。为支持无 TTY 的 Agent 工具，Secure `mem-save` 无 TTY 时只生成待审批请求，Private 仍需 TTY；pexpect 自动输入的审批不是人工确认，客户端和 CLI 同 UID 的身份隔离未验证。
