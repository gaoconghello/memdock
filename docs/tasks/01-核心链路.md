# 阶段一：核心链路

## 状态说明

| 标记 | 含义 | 使用条件 |
|------|------|----------|
| `[ ]` | 未完成 | 默认状态；对应开发、测试或验收事项尚未完成 |
| `[X]` | 已完成 | 开发项已核对实现并通过必要的开发方验证；测试项已执行通过；验收项已获用户明确确认通过 |
| `[>]` | 延后开发 | 已确认需要，但不在当前版本实现 |
| `[-]` | 不涉及 | 已确认当前方案不需要实现 |
| `[~]` | 已过时或被替代 | 不再作为当前完成条件；注明原因、原验证状态及适用的替代项 |

记录验证结果、环境和未覆盖项；阶段验收须经用户明确确认。以 [PRD](../prd/PRD.md) 和 [开发方案](../solution/开发方案.md) 为准。

## 开发方验证记录

- Linux x86_64；Go 1.24 容器中运行 `go test ./...`、`go vet ./...`、`go build ./cmd/server`，均通过；本机未安装 Go。HMAC 测试仅验证签名时效、内容绑定和防重放，不验证用户身份/确认。
- 脚本 `sh -n`、`git diff --check` 通过。临时 SQLite 服务端验证无 Git 同名项目选择、项目绑定、Git 子目录与 worktree 归一、多 remote 歧义拒绝、保存脚本确认及搜索；未解析项目的搜索 lookup 返回 404 且不创建项目/仓库映射。
- Docker Alpine 容器使用命名卷；保存后重启容器，搜索仍返回原记忆。
- Linux x86_64 本机真实客户端：Pi 1.6.0 通过 `--skill` 加载 `mem-search`、`mem-save`；Codex CLI 0.171.0 从临时 `CODEX_HOME/skills` 加载同一 Skill。默认项目、`MEMDOCK_PROJECT_ID` 指定项目及 `MEMDOCK_KNOWLEDGE_BASE_ID` 指定共享库检索均返回预期范围；Secure 保存 Skill 生成 mode 0600 审批请求，默认项目及共享库标签保存经独立 `approve-request` 后由对应 Skill 搜索读回，且标签通过详情 API 核对。Agent 只继承 read token，CLI 批准输入由 pexpect 自动模拟，不是真人确认；客户端和 CLI 同为 ubuntu UID 1000，严格身份隔离未验证。Secure `mem-save` 原先无 TTY 时拒绝运行，导致两个客户端工具无法生成请求；现改为 Secure 无 TTY 时仅生成审批请求，Private 无 TTY 仍拒绝。临时客户端目录和凭据未放入用户全局配置。
